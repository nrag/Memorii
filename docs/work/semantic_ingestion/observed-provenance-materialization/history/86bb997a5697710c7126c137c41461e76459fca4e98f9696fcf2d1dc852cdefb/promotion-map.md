# Canonical Promotion Boundary

The SIA opening delegates profile-3 public observation contracts to
`docs/design/semantic_ingestion_observation.md`. This amendment elaborates the
existing provenance/claim fields for that profile. Insert the approved recipe
in that addendum; preserve SIA and historical schema/profile bytes.

Root directly searched production/tools/workflows for the observation addendum
path and its current hash: no current executable hash pin consumes that prose.
The source models and registered schema field inventory do not change. Therefore
this prose-only promotion does not regenerate SIA binding-authority vectors,
source model declarations, registry cardinalities or historical release targets.
Record before/after addendum hashes in the promotion manifest and freeze the new
recipe candidate. Verify the unchanged SIA/model/registry bytes explicitly.

Prior design/component candidate manifests are immutable historical evidence;
do not rewrite their pinned inputs to pretend earlier checks used the new text.
The mapper suggestion to refresh all old candidate manifests is rejected for
this reason. Current detailed evidence belongs to this design package. Parent
plans receive only the current decision, status and next action.

Validation: bounded recipe tests, candidate/hash verification, identity hygiene,
and independent recipe review. This does not constitute runtime CI enforcement.
The public materializer, atomic snapshot-time binding and provider test must be
implemented and validated separately under the implementation WorkPlan.
