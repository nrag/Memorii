# Shared Observation Ledger Design Readiness Ledger

This is design readiness evidence, not a production closure claim. The target
contract is consolidated in docs/design/semantic_ingestion_observation.md, linked
from the governing SIA source. Construction documents below preserve derivation
and cross-references; they are not separate competing contracts. The user approved
the operational profile and separate temporal/trust projection observations.
Technical review is still required. SIA now includes that target link and native
policy-retention requirements; its affected source-derived chain must be refreshed.

For construction precedence, replay-snapshot-contract.md replaces the draft's
unspecified activation partition revision with the existing whole-store snapshot
revision and supplies the exact replay/checkpoint/cohort preimages.
operational-profile.md supplies profile publication details. All other source
requirements retain the repository's normal precedence. Construction maps and
feasibility programs are evidence, not alternative product contracts.

Schema publication readiness has two distinct outputs. Design review freezes
the finite model inventory, complete source-selected fields, declaration
language, construction preimages, protected deployment pins and independent
verification obligations. Implementation authors and verifies the concrete raw
role files, decoder source snapshots and complete vectors before a registry can
be activated. No digest or runtime publication claim is made from the inventory
alone. If a referenced model cannot be expressed by the closed declaration
language, that is a design gap, not an invitation for the implementation to
invent a schema. The earlier wording requiring generated bytes before any
implementation is superseded only for these implementation outputs; it does not
relax declaration completeness or publication verification.

## Requirement And Attack Coverage

| Requirement | Complete design boundary | Verification family |
| --- | --- | --- |
| Shared order | One repository head; delta semantic payload before assigned revisions | Two sources/group/source interleave; stale head; duplicate identity; zero-operation source |
| Atomic result and audit | Native result/member manifest, entry and mutable head share CAS | Crash/lost ack; late immutable collision; expired lease; stale admission; no partial publication |
| Exact registered bytes | Protected profile3 registry and fixed opaque-body envelope | Unknown/duplicate/substituted bindings; enum/optional/union forms; golden bytes; decoder spy |
| Historical compatibility | Existing profile2 literal readers, no audit upcast | Literal old bytes; no fabricated entries; new writes rejected under old admission after activation |
| Activation | Drained complete snapshot inventory and exact admission + snapshot CAS | Newly inserted control, active lease, stale inventory, wrong implementation/schema, rollback attempt |
| Replay completeness | Full typed prefix, result/graph links and independently read head | Prefix truncation, reorder, duplicate, changed payload/link, cross-repository chain |
| Checkpoint trust | State, unsigned preimage, signature, bundle and lifecycle receipt in acyclic order | Wrong key/time/repository/floor; forged prefix; stale publication CAS; missing links |
| Consistent authorized observation | Authorize before one detached store snapshot; full cohort preimage | Denial/outage no lookup; cross-scope expansion; missing source outcomes; mixed revisions |
| Contiguous authenticated paging | One immutable stream, protected creation time and exact cursor | Empty/final pages; N/N+1 limits; gaps/overlaps; changed policy/revision; revocation; eviction |

Schema attacks include direct and nested values, escaped Unicode keys, duplicate
JSON names and map entries, list/tuple/set distinctions, omitted/null fields,
literal/enum ambiguity, unknown versions and bool-as-int. The accepted
declaration grammar must define its supported forms; unsupported Python source
syntax is rejected rather than reflected. Positive cases accompany rejection
families, especially historical reads and legitimate protocol version numbers.

These are design binding plans at existing production triggers; the new calls
are not implemented. The parent implementation ledger must stay partial until
the later mapper proves actual callers and production execution.

| Existing production trigger | Required owner change and authority flow |
| --- | --- |
| atomic_store native group materialization (transaction-boundary.md) | Build exact canonical observations from retained planner/native reduction inputs; registered ledger payload -> assigned delta -> group result -> entry/head; preserve all existing source/graph guards in one batch |
| bootstrap_graph_terminal_preparation source publication | Seal source intent instead of assigned observation delta in terminal grammar3; assembler verifies intent against canonical source result |
| atomic_store terminal publication and immutable reload (terminal-grammar-map.md) | Store assigns global coordinates and actual native member; reload resolves exact locator/result/entry chain and verifies all bytes |
| SemanticWriterAdmissionStore transition and SemanticGovernedWritePolicy.validate | Drain old operations; typed activation+new admission+genesis CAS; all old mutation recognizers disallowed in activated epoch |
| MemoryPlaneService.conditionally_write_records -> backend apply_batch | Separate full write-revision CAS for activation/checkpoint; preserve existing data revision and append preconditions |
| Production graph observation facade | Protected authorizer -> MemoryPlaneService.read_write_snapshot -> registry/replay/cohort -> typed immutable stream; no provenance-index completeness shortcut |
| Observation checkpoint owner | Protected registry/lifecycle/key configuration -> complete replay -> signed preimage -> exact snapshot publication; no graph-checkpoint shape substitution |

The public observation facade and checkpoint owner are new required entrypoints,
not existing calls. Implementation readiness requires their composition in the
normal production root; helper-only evidence cannot satisfy their parent rows.

Concrete composition plan: `ProviderMemoryService` in core/provider/service.py
owns `observe_graph` and `observe_ingestion_time_attestations` methods delegating
to a required configured `GraphObservationService` for enabled observation.
Its protected runtime configuration supplies the authorizer, profile registry,
page policy, cursor signer/verifier and the existing `_memory_plane` and clock.
Authenticated context is the out-of-band host context in the canonical API,
never a request-body principal. An unconfigured/failed observation capability
returns the canonical non-disclosing denied response before any store lookup.
This is disabled capability behavior, not a fallback to an unregistered reader.

`BuiltInLocalHostSemanticIngestionCapability.build_semantic_ingestion_runtime`
in core/semantic_ingestion/capability.py and the canonical store construction in
ProviderMemoryService pass the same verified registry to writer admission and
SemanticIngestionAtomicStore when ledger mode is enabled. Activation refuses
any absent or mismatched registry. Existing pre-activation routes remain usable
under their historical admission. No alternate directly constructed store can
write activated ledger records without matching governed-write validation.
The observation checkpoint owner is `ObservationReplayService` in
core/memory_evolution/observation_replay.py; its privileged create method is
composed with the same memory plane/registry and protected lifecycle/key
configuration, and its read path is called by GraphObservationService. Public
observation methods never expose checkpoint signing or activation.

new versioned contracts; it must not silently overwrite frozen fixture-v2 rules.

Implementation gates include focused unit/contract tests, public native

## Review-Corrected Publication And Entrypoint Gates

The verified registry is a protected immutable history, not a mutable active
map. `active`, `replay_only`, and `retired` status is committed with each entry;
the registry history keeps every retained entry's original decoder/source
snapshot and rejects a conflicting same-coordinate entry. Deployment verifies
the external publication manifest, decoder-source-manifest, every whole-file
decoder snapshot pin, registry digest, and independent-vector manifest before
`ProviderMemoryService` receives the one shared registry object. This adds no
runtime activation claim.

Native accepted-group implementation must add immutable per-group projection
publication receipt/evidence members beside the mutable aggregate/checkpoint
pointers. The reload owner validates those immutable members after later groups
advance. Legacy group reload retains its original grammar with explicit absent
receipt dispatch; activated accepted publication requires the receipt. The
non-normative native projection map is not authority for a mutable-only receipt.

The concrete entrypoint matrix is
`entrypoint-verification-matrix.md`. Each listed proof must exercise the named
production composition root and demonstrate that removing its registry,
authorizer, admission, snapshot, or commit-owner argument fails. Unit helpers,
fixtures, and direct store construction cannot satisfy those gates.

## Evidence And Limits

Ordering/DAG model: 19 passed. Real memory-plane JSONL mechanics: four passed.
Authenticated cursor foundation: seven passed, not integrated. Literal source
terminal recovery retains its separately scoped evidence. None proves the new
profile registry, complete observation API, checkpoint lifecycle or all M5
requirements. Those are required implementation outcomes after design approval.

Resource controls are protected positive limits for bytes/nodes/depth, full
snapshot/stream size and finite CAS retries; no truncation is allowed. A full
prefix checkpoint intentionally retains history. This is a correctness-first
storage format, with no pruning or unbounded in-memory success guarantee.
