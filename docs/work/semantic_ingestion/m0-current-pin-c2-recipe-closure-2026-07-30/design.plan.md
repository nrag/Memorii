## Objective

Reconcile the frozen design's current C2 recipe authority with the current
56-schema Layer1 CTV authority and 148-heading registry so an implementation
can derive exact typed trust artifacts, canonical signature preimages, and the
complete structural/coverage/execution G1/G2/G3 byte closure without inventing
fixture values or using production verification as its oracle.

## Completion Contract

- the recipe format, eight normative roots, accepted grammar, exact current
  design/registry/authority/profile identities, and finite fixture inventory
  agree across design text and recipe bytes;
- every primitive value needed for trust, coverage, execution, report,
  environment, test/result/stream, release/history, pointer/history, and
  G1/G2/G3 transition artifacts is explicit and non-operational;
- every derived leaf names exact typed source selectors and a complete
  preimage/formula, forming one acyclic dependency graph;
- independent implementations may share only the frozen design, registry,
  recipe, standard cryptographic primitive specification, and declared
  canonical profile—not parser, normalizer, codec, generated bytes, or
  verifier-under-test;
- streaming or temporary-file materialization is explicitly permitted while
  preserving exact canonical bytes and per-member/content-addressed digests;
- a feasibility spike proves two independently authored paths can validate the
  recipe and reproduce the same current-pinned manifest identities without
  loading the complete structural artifact into one in-memory envelope;
- fresh spec, correctness, and test reviews leave no validated P1/P2 design
  defect or unresolved changes-required approval finding.

## Scope

Included:

- SIA-R03/R13 deterministic fixture authority only;
- the current normative C2 recipe schema and bytes;
- finite non-operational fixture values and G1/G2/G3 transitions;
- authority chain, streaming materialization, independence, and validation
  matrices.

Excluded:

- production implementation changes;
- M1 result lookup;
- C3 repository/index/fence redesign;
- operational keys, custody, releases, activation, or certification;
- changing Layer1 design, registry, authority, or profile semantics.

## Constraints And Invariants

- historical C1/C2 artifacts are provenance only and cannot be repinned as
  current authority;
- no generated digest, signature, envelope, coordinate, root, or expected
  verdict may be copied into primitive authority when it is derivable;
- fixture authority cannot authorize production or satisfy
  `SIA-ED-TRACEABILITY-001`;
- complete structural, coverage, and execution bytes remain mandatory even
  when streaming is required;
- unknown, incomplete, ambiguous, circular, or mismatched inputs fail closed.

## Scenario-First Authority Amendment

The user superseded the impossible field-first expected-output authority. The
normative primitive is now the closed semantic scenario contract in
`docs/design/semantic_ingestion/scenario_first_fixture_authority.md`, with its
finite initial authority in
`docs/design/semantic_ingestion/traceability_golden_vectors/scenario-first-v1.json`.

The renderer receives only scenario relationships and produces ordinary source
observations. The real `EnglishRuleMemoryExtractor` receives only those
observations. Hidden scenario truth is available only to the independent
comparator. The comparator ignores generated IDs/order but preserves claim
cardinality, arguments, polarity, modality, attribution, temporal bounds,
scope, provenance, and abstention. The currently supported round-trip subset
is direct positive `owner` and `status` assertions; unsupported forms remain
explicit negative/ambiguous/insufficient-evidence cases rather than invented
passing semantics.

Fixture 35 is therefore specified as current-v2 typed input derived from one
rendered interaction and actual normalized extraction evidence. Structural,
coverage, execution, and G1/G2/G3 artifacts derive from pinned source plus
actual run bytes and a fixed test-only administrative state. Registered
operational-shaped bodies use a deterministic test root present only in the
scenario test configuration; default production trust lookup excludes it. They are no
longer field-table primitive authority. The direct expected-artifact-table
alternative was rejected because it needs the prior 1,452 unknown operands and
would permit self-authored expected evidence.

### Scenario-First Public-Ingress Closure (2026-07-30)

C2 derivation. It remains read-only migration provenance and is not an input,
pin, or expected-output oracle for scenario-first fixture generation. The
current root set is: scenario bytes; renderer, comparator, and ingress-runner
source bytes; public-ingress run bytes; design and registry bytes; and the

content-addressed from those roots.

uses `ProviderMemoryService.sync_event` and `MemoryPlaneService`, rather than

fails if an oracle-shaped field reaches extraction. The run produced four

`elaborate_scenario_a.py` and `elaborate_scenario_b.py`, consume only raw
