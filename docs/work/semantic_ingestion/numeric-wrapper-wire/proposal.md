# Proposed Numeric Wrapper Wire Forms

Status: existing-map choice approved by the user on 2026-09-07; precise amendment
under review, not yet a replacement for the governing design.

Use the existing canonical CTV map representation for both numeric primitives.
The selected schema TypeExpr fixes which exact map is valid; a caller cannot
select a numeric type using an unregistered tag or a body hint.

## Binary64

Exactly one member, ieee754_hex, containing exactly 16 lowercase hexadecimal
digits. The bits are network byte order. NaN, infinity and negative zero reject;
positive zero, finite negative values and subnormal finite values remain valid.
For example, the exact bytes representing one are:

```json
{"$type":"map","entries":[["ieee754_hex","3ff0000000000000"]]}
```

No JSON number, native float, additional member or alternate tag is accepted.

## Decimal

Exactly two members: encoding_spec_id and fixed_scale_value, in canonical map
key order. Both are strings. Example exact bytes under an explicitly selected
scale-two policy named example.quantity.v1:

```json
{"$type":"map","entries":[["encoding_spec_id","example.quantity.v1"],["fixed_scale_value","1.25"]]}
```

Add the required member encoding_spec_id to each object in numeric-role.fields,
alongside that object's field_name and representation; it is never a top-level
numeric-role member. The exact amended object grammar is:

```text
object{field_name: ascii-id,
       representation: "canonical_decimal_quantity" | "canonical_finite_binary64",
       encoding_spec_id: ascii-id | null,
       unit: string | null, scale: positive-uint | null,
       lower: string | null, lower_inclusive: bool | null,
       upper: string | null, upper_inclusive: bool | null,
       reject_inexact: bool | null}
```

encoding_spec_id is non-null for decimal fields and null for binary64 fields;
omission rejects for both. Decimal IDs are unique across distinct field
declarations identified by (schema_id, schema_version, field_name) in one
published source package. Traversing the same declaration through multiple
model closures is not a duplicate. The body ID must equal the
exact selected field's row ID, never an ambient/current-policy lookup. An
author can give different schema versions distinct explicit IDs.

The existing numeric closure digest commits the complete raw row, including
the ID. No new independent hash algorithm is introduced. Duplicate IDs, missing
IDs, a binary64 row with an ID, or a body naming another field's ID reject.

The selected row fixes unit, positive scale, bounds and inclusivity. The value
must use the existing SIA fixed-scale lexical grammar and satisfy that row's
range. No exponent, plus sign, leading zero, negative zero, scale omission or
rounding is permitted. The existing Boolean reject_inexact remains committed
metadata; false cannot override SIA's prohibition on rounding. This proposal
adds no generic lower/upper ordering requirement beyond governing domain rules.

## Common Boundary And Verification

Both bodies use only the existing map and scalar tags. Their maps reject missing
or extra fields, wrong scalar types, duplicate or misordered keys, malformed
Unicode, noncanonical JSON and trailing LF. Verification remains schema-first
after protected embedded-binding selection. Decode/re-encode must preserve the
exact bytes. These primitives are not independently selectable unregistered
root models; they are values of a registered field.

Tests must cover both exact positive examples; zero/subnormal/negative binary64;
NaN/infinity/negative zero; decimal endpoints and inclusivity; wrong scale and
wrong ID; malformed or extra map members; and mutation of the numeric-row ID
changing the affected policy/binding commitments. The independent compiler
must parse the new row independently from raw source. Neither compiler may
derive an ID from a runtime class, reflection or an invented naming convention.

An alternative with two new numeric tags is possible, but requires changing
the closed literal grammar and profile commitment. Reusing the existing map
form keeps the tagged-value algebra stable while making every numeric member
and policy association explicit.
