## Objective

Implement the approved broad default ontology and framework-neutral learner through real Memorii composition roots. The default path must retain and read authorized memory and accept an authenticated structured fact with no Memorii-owned OpenAI API key. A host, local, or explicitly configured remote model may supply raw-text extraction or ontology discovery; absent that capability, free-text discovery remains visibly pending. Ship 53 semantic relations across twenty workplace personas and ten single-account home journeys, plus the separate user-context preference record, before relying on learned extensions.

## Completion Contract

Complete this Level-2 operation when the intended manual-test journeys are runnable end to end: no-key structured memory; one versioned fourth relation; the broad workplace/home default catalog; coverage observation; and one learned-candidate evaluation, activation, rollback, and replay loop. Each journey needs its ordinary happy scenarios, basic caller and scope isolation, persistence/restart, retry/recovery, and common invalid-input behavior. Focused deterministic checks must prove those paths and leave `remaining_validated_p1_p2: []` for supported Level-2 behavior.

Do not require production scale, exhaustive relation permutations, hostile-storage mutation families, full platform matrices, release packaging, migration ceremony, exact CI release evidence, or whole-branch production approval before manual testing. Record those obligations in the deferred release-conformance packet and start them only after manual validation moves the work to Level 3. A passing helper or direct constructor still does not establish a runnable manual journey.

## Scope And Decisions

Included: typed catalog/type/value policy source; provider-neutral capability and no-key structured-fact port; generated provider schema/prompt and semantic policy bindings; semantic and user-context writer/reader paths; immutable catalog registry and activation pointer; observation, candidate, evaluation, replay, status, and recovery; first-party adapter plus a second independent adapter conformance path; migration and release evidence.

Excluded: cross-account household sharing, model-defined executable validators, new top-level learned entity roots, in-place relation mutation or deletion, inference of fact truth from catalog activation, and silent remote model fallback. `Household` is an entity inside one signed-in user's scope, not an access principal. No design deviation is approved. Any new public, persisted, authorization, or domain semantic not settled by the approved design returns to `$build-design` before implementation.

The existing OpenAI-only `gpt-4.1-nano` extractor is a compatibility baseline, not a dependency of the new core ontology service. No API key is needed for deterministic catalog and structured-fact operations. Arbitrary raw-text extraction without a bound model remains unavailable and must report that limit accurately.
