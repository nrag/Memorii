## Objective And Requirement Source

The approved ontology design requires the verified active catalog owner/digest to be durably pinned before provider-facing proposal egress. The M2 installed `reports_to` trial adds a stricter observable boundary: Hermes `get_tool_schemas` must advertise only the same catalog that `handle_tool_call`, the proposal adapter, writer and protected reader subsequently verify. The existing Hermes captured-turn identity is durable before schema display, but the only retained structured operation identity is allocated later from a proposal-containing envelope. The implementation worker stopped without product edits rather than invent a pin source or an ungoverned record.

Define the smallest typed, authorized, persisted pre-schema pin tied to the captured turn. Preserve source capture when catalog processing is unavailable, the existing three-relation no-key path, candidate-versus-committed separation, current grants and the protected historical reader. No household sharing, learner activation, full 53-relation bundle or production release proof is included.

## Current Reality And Alternatives

`HermesCapturedTurnLedger.capture_id` is stable at schema time; `HermesCapturedTurnCoordination` joins that ledger and retained source. `get_tool_schemas` currently reads an in-memory active handle and emits a fixed three-relation grammar. `submit_structured_fact` allocates a core retained operation only after tool arguments/proposal exist. `SemanticCatalogAuthorityAdministrationAuthorization` permits only the two-record seed genesis; capture publication uses the semantic writer's governed source-only atomic closure. No current record binds a captured turn to the catalog selection pointer before schema egress.

Consider (1) include the pin in source capture CAS, (2) use a separate governed CAS after capture and before schema display, and (3) defer pinning to tool submission. Option (1) risks blocking otherwise valid raw-source capture whenever catalog selection is unavailable. Option (3) permits advertised grammar to change meaning before submission and violates the approved pre-egress rule. The draft should prefer (2) if a verified ledger/coordination/current-pointer read and preconditions can make its authorization and retry semantics complete. No integration-side direct storage write is allowed.

## Contract To Freeze

Specify a behavioral persisted pin ID derived from `capture_id`, exact closed fields and digests, selected owner/version/digest and capability identity, source/ledger join, protected scope, source kind and visibility. Define one canonical core owner, one writer-admission authorization, preconditions across capture/coordination and selected pointer, and the fate of a losing concurrent CAS. A present invalid pin must fail closed without reselecting the current pointer. A valid existing pin remains selected for that capture after pointer rotation, including schema repeat, tool submission and retry. The pin cannot grant fact or catalog visibility by itself.

Specify installed factory/runtime arguments and the exact path from `on_turn_start` capture through `get_tool_schemas`, catalog resolution, durable pin, artifact verification, schema emission, `handle_tool_call`, retained proposal envelope, terminal binding, and protected read. A captured turn without a valid selectable catalog still retains its source but advertises no semantic tool; no model transport is required for the structured path. Restart may verify the durable pin but must not restore a live tool handle. Existing unbound pre-catalog records continue through their verified legacy reader only.
