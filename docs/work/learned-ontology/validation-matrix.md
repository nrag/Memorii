## Catalog And Attack Equivalence Classes

### Active Fourth-Relation Checkpoint

The first versioned-catalog production probe uses the normative `reports_to(Person, Person)` declaration. Its direct positive and collaboration/quotation/hypothetical near misses must pass through the same installed parser, semantic policy, writer and protected reader; Person and entity value are existing codecs, while private fact scope and multi/set state policy are new relation-bound behavior. A seed genesis, four-relation child, active-pointer CAS, pin-before-egress retry, actual pre-upgrade old claim, missing/corrupt active child, and disabled legacy reader must be exercised over persisted storage. A test that only constructs `PredicateProposalCatalog` in memory cannot establish this checkpoint. The active M2 packet contains the exact accepted and rejected matrix; no M2 fixture has run yet.

Use one typed declaration and generated authority chain rather than 53 hand-maintained prompt/schema switches. For each base relation, assert exactly one declaration, matching subject/object kind, evidence class, scope, lifecycle, literal policy if any, read form, and primary persona/home code. Generate behavior fixture names from relation IDs; the fixture predicate must match the row. `H8` is a separate user-context record. A missing row, duplicate ID, orphan coverage code, stale generated artifact, or unsupported codec blocks the entire default bundle. Add representative direction swap, self-edge/cycle, alias, negation, quotation, reported/hypothetical, competing entity, correction, temporal, private scope, and historical-read cases by relation family, plus relation-specific four-case fixtures for every row.
