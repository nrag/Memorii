## Problem And User Journey

Milestone 1's verified generic core port now commits and reads a no-key fact, survives JSONL restart and denies revoked access. The installed Hermes binding still has no caller for that port. Its external provider advertises no tools and rejects calls; the factory issues no structured authority; prefetch supplies no structured fact read authority. A normal retained old V3 claim in the same scope returns `UNAVAILABLE` under the candidate legacy verifier because schema-1 group history has no later receipt/ledger join. The approved design requires an installed adapter journey and continued old-record reads. The single signed-in user's account remains the sole household fact scope; no cross-household access is introduced.

Desired end-to-end outcome: a signed-in Hermes user speaks a fact, the host retains the authentic user message without a Memorii OpenAI key, the agent supplies a typed proposal tied to an exact retained quote, core validates and commits, protected recall works after restart, and pre-catalog facts retain their original meaning/authorization. Another agent adapter can use the same generic core port with its own host evidence; ontology discovery remains provider optional.

## Authority And Scope Boundaries

The addendum may define only the first-party Hermes tool/host evidence and the original schema-1 compatibility reader. Core `submit_structured_fact`, typed proposal stages, catalog binding, current-grant native CAS, and single-account scope remain governed by the approved design and implementation. Neither agent-generated assertion text nor a current sidecar catalog digest can become historical source or catalog proof. Model output cannot issue grants. The first-party host signs/reconstructs identity from the local installation and signed-in callback, and core resolves the catalog.

Excluded: new shared-household principals, arbitrary text-to-fact extraction without a configured model, inferred old-to-new catalog binding, a fourth relation, ontology learner, new top-level entity root, and a remote fallback. Level 3 packaging, migration/rollback certification and hostile-storage attack breadth remain parent release obligations.

## Alternatives To Resolve

| Legacy schema-1 reader | Keep `UNAVAILABLE`; rerun old records under new catalog; validate the original schema-1 committed storage closure; add a new upgrade seal | The first violates old-read compatibility, the second invents catalog meaning. The read-only feasibility probe found a complete source, group-primary, committed-result, effect and deterministic-projection chain in the original atomic store. Prefer validating that exact chain under the original trusted-store model. A new seal is optional future evidence; it cannot retroactively prove historical commit or change meaning. |
