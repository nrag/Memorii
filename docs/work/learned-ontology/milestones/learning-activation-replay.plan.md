## Journey And Boundary

A verified recurring relation or registered-parent subtype gap yields one inert typed candidate. Closed parsing and registered validator/identity/value/evidence policies reject unknown edits and collisions. A frozen parent-versus-candidate paired run proves targeted gain and no regression or scope/provenance failure. The authorized agent-scope owner may approve after mandatory gates; automatic agent-local activation is disabled until the exact binding's labeled cohort supports the 0.95 score and one-sided precision lower-bound rule. Publication appends an immutable version; `activate_candidate` selects it through prepared/selected CAS. `select_prior_version` may roll back only to a prior selected same-scope ancestor. Eligible retained sources replay through the ordinary writer under current grants; catalog acceptance itself writes no fact.

## Owners And Changes

Implement the closed `OntologyChangeProposal` edit grammar, durable state transitions, evidence references, type/alias/value-policy validation, evaluator and calibrated policy, scope-owned immutable registry, `OntologyActivation` attempt/pointer, status and recovery. Proposal IDs and catalog digests are core-derived; a model cannot select authority. Build lineage-disjoint development, paired acceptance, calibration and final-audit corpora with exact provider/prompt/catalog manifests. Use the existing source-preparation, semantic validation, grant-fenced writer and protected historical reader for replay; retain original source and version identity. No arbitrary root type, in-place mutation, cross-scope auto promotion or model-defined executable code.
