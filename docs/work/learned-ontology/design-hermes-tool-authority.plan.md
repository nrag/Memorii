## Problem And Evidence

The installed Hermes turn-start capture is locally verified, but a real `memorii_submit_fact` tool cannot yet construct the existing typed `StructuredFactSubmissionRequest`. The factory's `_LocalLevel2StructuredSubmissionResolver` validates grants supplied by a caller and selects the packaged catalog; it does not issue `SourceScopeGrant`, `FactScopeGrant`, or `CatalogOwnerVisibilityGrant`. Production grant IDs and versions control same-store revocation and are persisted in structured submissions and claims, so the adapter may not improvise them. The existing preparation stores exact sentence and token `SourceSpanReference` values, but the tool specification lacks a deterministic rule for mapping its `source_quote` and optional scalar offset to one retained span. These are contract details exposed by implementation, not a change to ontology grammar.

## Scope And Alternatives

Specify a factory-owned local grant issuer with deterministic per-installation, principal, agent, kind and scope identity; version 1 for the first local grant generation; no automatic reactivation after same-store revocation. Source grant covers the signed-in user's captured project task source, fact grant covers only that user's fact scope, catalog grant covers the core-selected base owner. The request contains exactly those issued grants; the existing resolver revalidates them and core persists/rechecks their current state. An untrusted tool argument cannot choose any grant coordinate. A random per-tool-call grant ID would defeat revocation; one shared grant for all three concerns would defeat independent revocation. Both are rejected.

Map `source_quote` to exactly one retained `PreparedSource.sentence_spans` item in the captured user's segment. `source_quote_start`, when present, must equal that span's Unicode-scalar start in the retained user message; without it, multiple equal sentence spans are ambiguous. Subject, predicate anchor, object and temporal quotes must resolve uniquely within the selected sentence and match the closed proposal grammar from the reviewed addendum. The host passes the exact stored span as the only `exact_source_spans` member, ordered by its digest, then core rechecks it. The tool cannot synthesize a span from provider text or assistant text. Arbitrary multi-sentence quotes are rejected for this initial tool. A proposal-only interface without source citation is rejected because it cannot prove user provenance.
