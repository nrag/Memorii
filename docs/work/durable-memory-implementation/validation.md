## Equivalence, Mutations And Positive Controls

Closed request/record/event/query/selector/control languages: cover every registered discriminator/version, all required/unknown/null/missing fields, wrong scalar/enum types, nonfinite numbers, malformed timestamps, duplicate aliases/IDs, nested/quoted/planning-derived values, ordering and equivalent canonical encodings. Aliases/inheritance not accepted by a registry are rejection cases, not features to add. Test direct/fast-path/normal-path ingress with the same family. Always retain valid boundary/canonical positive cases.

CAS family includes absent/digest/fence, expected data/write revisions, unconditional supported writes and current grant transaction checks. Publication family includes semantic-only/ontology-only/runtime-only updates, unchanged-domain heads, bootstrap/adoption/checkpoint-only transitions, same-head materialized-row/index mutation and every old/new/third selector. Lifecycle family enumerates every permitted and forbidden attempt/outbox/action/control/migration transition, lease expiry/reclaim and current authority at commit/release.

Identity family: field-aware checks on Python/export symbols, SQL catalogs, schema discriminators, tool/CLI/entrypoint manifests, generated API/TS artifacts, fixtures and CI labels must reject M1/M2/M3/C2/R22/SIA-R22 including prefixed/snake/kebab variants. Positive controls include BM25, genuine protocol v1 and exact documented historical migration values. No blanket file/directory exemption. Traceability IDs stay in typed traceability fields only.

Independent replay proof: a separately authored reducer cannot import or copy production replay, normalization, materialization or reference control flow. Shared frozen canonical encoded fixtures and standard cryptographic/serialization libraries are allowed only as the design permits; record shared dependencies. Compare complete output and failure classes, not only a summary hash. Two runs of one reducer are reproducibility, not independence.
