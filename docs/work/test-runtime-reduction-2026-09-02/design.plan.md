## Objective

Reduce the locally experienced full-suite runtime from the 8h15m
pre-optimization serial baseline (post-optimization serial expected
~2.5-4h, to be confirmed by the linked operation's CE-9 broad gate) to
approximately 30 minutes ±15, without weakening any assertion, family,
threshold, or gate.

CE-9 rerun launched one revision before its own fix landed and was
stopped at ~10% as wasted time.  Every gate launch in this operation

## Phase 2 — The Fix Design (v4, from the measured CE-9 baseline)

Measured post-optimization serial baseline (CE-9 gate, `c9995a1`, load
~8): **4h24m** for 4,076 nodes (pre-optimization 8h15m; quiet-machine
expectation ~2.5-3.5h). Loaded composition estimate:
`test_bootstrap_graph_production_roots` ~120-140m (race ~60-75m
including ~23m of 200 subprocess spawn/import tax; in-memory replay
~35-45m; other families ~15m), `semantic_terminal_persistence`
~25-35m, other `semantic_ingestion` ~25-35m, `tools` ~45-55m, core
misc ~10-15m. CI facts (corrected in review round 1 — the original draft falsely
claimed no dedicated PR job): `production_roots` is ignored by the 4
file-scope shards, but **~200 of its nodes (≈87% of its runtime) run in
CI** through the `bootstrap-graph-transaction-boundary` job family (8
matrix jobs, 90-min timeout, selectors generated by
`memorii.tools.bootstrap_graph_transaction_selector` from a path
constant, manifest `tests/ci/bootstrap-graph-transaction-boundary.json`);
the remaining cost is local-only. The durations artifact regenerates
via `memorii.tools.test_shards`, which consumes only its own
timing-plugin JSON artifacts — there is no junitxml path.

**Target: 15-45 minutes wall for the complete local suite.**

### L1a — Split `test_bootstrap_graph_production_roots.py` (not a pure move: a coordinated consumer update)

Live collection yields **257 nodes** (the durations artifact's 241 are
stale — a later parametrization widened two families to 16 each), so
all identity proofs baseline from live `--collect-only`, never the
artifact. The split into per-family modules (behavioral names:
race-reopen, scenario-replay, root-composition families) carries a
**definition-of-done consumer set** (review round 1, test reviewer P1):

1. A shared support module (the `graph_record_test_support.py`
   pattern) carries `_GRAPH_SCENARIO_BEHAVIOR`, `_graph_fact_proposal`,
   `_RemovedBootstrapGraphHostBundleBuilder`, `_provider_service`,
   `build_provider_memory_service_from_env`, `build_filesystem_provider`,
   `_hermes_provider`, `_builders`; the process runner's import of the
   first three (currently from the test module,
   `bootstrap_graph_v3_process_runner.py:29-33`) re-points to it — a
   miss fails at 100 nodes' runtime, not collection.
2. `memorii/tools/bootstrap_graph_transaction_selector.py:68-72` path
   constant updated; `tests/ci/bootstrap-graph-transaction-boundary.json`
   regenerated via its `--write` flow so the 200-node CI boundary
   coverage is **provably retained** (losing it would be coverage
   weakening).
3. `tests/ci/unit-shards.json` `--ignore` entries re-pointed at the new
   family module names at split time (before L4), or the families
   routed to dedicated jobs — otherwise ~130m enters 4 shards with a
   600s target.
4. The two pinning unit tests updated
   (`test_bootstrap_graph_transaction_selector.py:141`,
   `test_static_tooling_config.py:403`).
5. Identity guardrail (restated to be satisfiable): node IDs equal
   **modulo the path component**, parametrized suffixes unchanged, and
   live-collected count equal (257) before/after.

### L1b — Parallel local execution via pytest-xdist

`pytest-xdist` (dev dependency via `uv`, user-approved; not installed).
Distribution mode decided by a **strengthened equivalence protocol**
(review round 1, both reviewers):

- Static hazard sweep recorded as design evidence (whole tree: no
  session-scoped fixtures, no sleeps/chdir/absolute-tmp writes, no
  module-level env mutation; subprocess users all write under per-test
  `tmp_path`; process-based workers make monkeypatch patches safe).
- Serial baseline run + **at least two parallel repetitions at varied
  worker counts** (affordable at the target wall), same quiet revision,
  explicit flag parity with CI (`-W error`, `-p no:cacheprovider`,
  cwd `memorii/`).
- **Node-granular outcome comparison**: pass/fail/skip/xfail plus
  warnings-under-`-W error` per node, all runs equal.
- Pre-declared contention policy: no retries — a subprocess timeout
  under worker contention is a failure to investigate, never silently
  retried; `--dist loadfile` reproduces whole-file assignment (not the
  full CI 4-process structure); `--dist load` additionally requires the
  per-node sweep conclusion to hold, which the repetitions test.

### L2 — Race-family process batching

Manifest elements are per-element records
`(storage_root, root, scenario, phase, output_path)`; each first/reopen
pair shares one `storage_root`, and roots are never shared across
scenarios. Batch-safety evidence (verified in review round 1): the
runner constructs the store per element from `storage_root`
(instance-scoped identity-keyed caches; per-operation fcntl locks — a
fresh same-process handle re-reads persisted state), the `first`-phase
on-disk rewrites are visible to the paired `reopen`, and no module
along the runner path holds mutable global state — so reopen
equivalence reduces to fresh-handle disk reload. Required hardening:
the dead `reused_committed` module-global patch in the runner
(`:207-225`, class never instantiated) is deleted or restored via
try/finally; a module-global-mutation audit is part of the L2
definition of done. Per-element timeout: a per-element alarm-style
guard with fail-fast that identifies the failing element index in the
output (aggregate outer budget = 180s × elements). Adoption gates: the
**200 per-scenario outputs byte-identical between batched and
unbatched modes** at the same revision, and one canary scenario pair
permanently retained on the two-subprocess path.

### L4 — Timing-evidence regeneration (corrected flow)

Regenerate via the flow CI actually uses: per-shard
`test_shards run --config tests/ci/unit-shards.json --index N
--timing-output ...` from a **green** tree (the merge fails closed on
any red artifact and on plan-digest mismatch with live collection),
then `merge`; repeat for the terminal-persistence dedicated inventory;
then re-point/verify the shard config against the split files.
Acceptance: the identity-hygiene gate green post-regeneration (the 124
stale structured keys close here), and every new node ID
coordinate-pattern-clean (new module names included). No junitxml path
exists or is added.

### Guardrails

- No assertion, family, threshold, or coverage change; the file split
  proves node identity modulo the path component with live-collected
  count equality (241), retains the 200-node CI boundary coverage
  provably, and the identity-hygiene allowlist pins no node IDs (only
  four traceability field values), so it survives the split.
- The serial command remains available and equivalent (results must
  match the parallel run at the same revision).
- CI structure stays authoritative; local changes document command
  equivalence against the shard config; the split rebalances it.
- Determinism preserved: no wall-clock or sleep dependencies; xdist
  must not change outcomes (the equivalence experiment is the gate).

## Phase 3 — Contract And Guardrails

- No coverage weakening anywhere; any proposed matrix change requires a
  retention map and discriminating-failure proof per the design-tests
  contract.
- The 4-shard CI structure and its dedicated jobs remain authoritative;
  local changes must document command-equivalence against them.
- The durations artifact is regenerated after material test moves via
  the existing `memorii.tools.test_shards` merge flow.
- Deterministic behavior preserved: no wall-clock, sleep, or ambient
  randomness dependencies introduced; xdist distribution must not change
  any test's outcome (verified by a full pass/fail comparison).
- Identity hygiene: no planning-coordinate names in new runner scripts,
  jobs, or fixtures.
